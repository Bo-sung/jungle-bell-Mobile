## 이 포크에서 추가된 것

기존 React 웹 앱(PWA)을 그대로 재사용하는 **Capacitor 기반 Android 앱**과, 네이티브 Kotlin으로 구현한 **홈 화면 위젯 6종**입니다.

| 구성 | 설명 |
|---|---|
| 앱 본체 | Capacitor WebView가 프로덕션 웹앱을 로드. 앱 기능(페어링, 알림, 세탁, 식단, 출석)은 웹 코드와 100% 동일 |
| 홈 화면 위젯 | 네이티브(Kotlin + RemoteViews). 30분 주기 WorkManager 동기화 + 로컬 캐시 |
| APK 자동 빌드 | `main` 푸시마다 GitHub Actions가 APK를 빌드해 [Releases](https://github.com/Bo-sung/jungle-bell-Mobile/releases/tag/android-latest)에 자동 게시 |

### 위젯 기능

| 위젯 | 크기 | 내용 | 데이터 원천 |
|---|---|---|---|
| 식단 | 2×2 | 오늘 메뉴 **사진 배너** + 현재 끼니 텍스트 (오후 2시부터 석식 우선), 메뉴가 없으면 "오늘 휴무" | 공개 API (`/api/public/meals`) |
| 식단 상세 | 4×2 | 중식 + 석식 전체 메뉴 텍스트를 나란히 표시 | 공개 API (`/api/public/meals`) |
| 세탁 | 2×2 | 세탁기·건조기 요약 (사용 가능/사용 중/예상 종료) | 아래 "워시타워 직접 연결" 또는 공개 API |
| 세탁 상세 | 4×2 | 기기별 남은 시간 9줄 상세 | 동일 |
| 워시타워 | 4×1 | 세탁탑 9열 그리드 색상 그림 (구역별 색) | 동일 |
| 출석 | 2×2 | 앱의 "오늘 출석" 카드와 동일한 구성 — 학습 시작/종료 완료·미완료 체크 셀 + 마지막 동기화 시각 | 페어링 세션 쿠키 (`/api/me/attendance`) |

- **식단/세탁 위젯은 공개 정보만 사용**하므로 PC(서버)가 꺼져 있어도 계속 동작합니다.
- **출석 위젯만 개인 데이터**라 앱에서 PC와 페어링(`__Host-jb_device` 쿠키)이 필요합니다. 미페어링 시 "앱에서 PC와 연결" 안내가 표시됩니다.
- 식단 사진은 동기화 시 720px로 다운스케일해 미디어 해시 이름으로 캐시하므로, 같은 사진은 재다운로드되지 않습니다.
- **앱에서 새로고침하면 위젯도 함께 갱신됩니다** (세탁은 즉시, 식단·출석은 5분 제한 미러). 위젯 단독 갱신은 최악 30분 주기입니다.

### 앱 측 Android 전용 처리

- 상태바/제스처바 겹침 해결: 콘텐츠 프레임에 시스템바 인셋 패딩 적용 + 하단 네비 safe-area를 네이티브 측정값으로 JS 주입
- 러버밴드 오버스클 비활성화로 fixed 하단 네비가 스크롤 시 밀리지 않음
- 앱 아이콘/알림 아이콘을 실제 로고로 교체, 다크 모드 WebView 배경 대응
- 네이티브 알림 테스트 버튼(앱 내)으로 Android 알림 파이프라인 확인 가능

### 워시타워 직접 연결 (QR 한 번 등록)

모니터링 사이트 주소(터널)는 재시작 시 바뀔 수 있어서, 앱 안에서 원천 주소를
직접 등록하는 구조를 제공한다. 주소는 기기에만 저장되고 저장소·서버로 전송되지 않는다.

1. 세탁실 게시 QR을 폰 카메라로 스캔 → 앱의 "워시타워 소스 연결" 화면 자동 오픈
   (일반 URL QR도 링크 선택지에서 Jungle Bell 선택 가능), 또는 앱 내 "🧺 소스 연결" 버튼에서 수동 입력
2. [검증 후 저장] → 이후 세탁 데이터는 서버 없이 해당 주소에 직접 접속해 갱신
   (위젯 30분 주기 + 앱 내 새로고침 시 즉시)
3. 주소가 바뀌면(터널 재시작) 새 QR을 다시 스캔하면 즉시 복구. 소스가 죽어 있으면
   위젯에 `⚠ 소스끊김` 표시

QR 인코딩 형식: `junglebell://laundry-source?url={인코딩된 소스 주소}`

참고: 앱 안에서는 서비스 워커를 등록하지 않고 해제한다. SW가 `/api/public/*`
fetch를 중계하면 네이티브 요청 가로채기(직접 소스 스왑)를 우회하기 때문이다.
앱 안에서 PWA 오프라인 캐시·웹 푸시는 동작하지 않는다.

## 주의사항

- **서버 알림(세탁 종료·사용 가능 알림)은 앱 직접 연결과 무관합니다.** 서버가
  원천 주소를 알아야 동작하므로, 서버 측 수집이 끊기면 위젯/앱 화면은 직접
  연결로 살아 있어도 알림만은 멈출 수 있습니다.
- **남성/여성 세탁 가능 횟수 계산**은 서버 전용 로직(최근 7일 위험도 반영)이라,
  워시타워 직접 연결 모드에서는 앱 화면에 "최신 기기 상태 확인 중"으로 표시됩니다.
  기기 상태 자체는 실시간입니다.
- **위젯 갱신 주기는 최악 30분**입니다 (푸시 기반이 아닌 폴링). 삼성 배터리
  최적화에 묘이면 주기가 밀릴 수 있으니, 지연이 잦으면 배터리 사용량 최적화에서
  이 앱을 제외하세요.
- **세탁실 QR/소스 주소는 시설 이용자끼리만 공유하세요.** 주소 자체가 접근
  권한(어원 토큰) 역할을 하며, 앱은 주소를 기기 밖으로 전송하지 않지만
  주소를 아는 사람은 누구나 세탁 상태를 볼 수 있습니다.
- **출석 위젯은 PC 앱이 켜져 있고 페어링되어 있을 때만 최신값**을 받습니다.
  PC가 꺼져 있으면 마지막 수집 시점 데이터에 `· 오래됨` 표시가 붙습니다.
- **CI APK는 디버그 서명입니다.** 고정 디버그 키스토어(리포 커밋, 표준
  android/android 자격 증명)로 서명하므로 CI 빌드와 로컬 빌드가 상호 덮어
  쓰기 설치가 가능합니다. Play 스토어 게시용 릴리스 서명 키와는 무관합니다.
- 워시타워 소스가 죽어 있으면 위젯·앱은 서버의 마지막 데이터로 폴백하며
  위젯에 `⚠ 소스끊김` 표시가 붙습니다. 새 QR을 스캔하면 즉시 복구됩니다.

## Android 설치 방법

### 방법 A — GitHub Releases에서 APK 다운로드 (가장 간단)

[Releases › android-latest](https://github.com/Bo-sung/jungle-bell-Mobile/releases/tag/android-latest)에서
`JungleBell-android-debug.apk`를 폰으로 내려받아 설치합니다. `main` 푸시마다
자동으로 다시 빌드되어 같은 링크가 최신 APK로 갱신되고, 설치된 앱 위로
덮어쓰기 업데이트가 됩니다 (고정 디버그 키). 설치 시 "알 수 없는 앱 설치"
허용이 필요합니다.

### 방법 B — 소스에서 빌드

**요구 사항:** Node.js 20+, JDK 21, Android SDK (Platform 36), 실기기 또는 에뮬레이터

```bash
# 1. 웹 에셋 빌드 (frontend/ 기준)
npm ci
npm run build

# 2. Android 프로젝트 동기화 (첫 빌드 전 1회)
npx cap sync android

# 3. 빌드 + 기기 설치
cd android
./gradlew :app:installDebug        # macOS/Linux
gradlew.bat :app:installDebug      # Windows
```

- `android/local.properties`는 머신별 값(SDK 경로 등)이라 커밋되지 않습니다. Android Studio로 프로젝트를 열면 자동 생성됩니다.
- 디버그 서명으로 바로 설치되며, 앱 실행 후 앱 안에서 PC와 페어링하면 출석 위젯도 활성화됩니다.

## iPhone 빌드 방법 (및 인증서 관련)

iOS 빌드는 **macOS + Xcode**가 필수입니다. (Capacitor iOS 플랫폼 특성)

### 작업 현황과 남은 일

- `npx cap add ios`로 플랫폼을 추가한 뒤, Android에서 한 처리를 iOS에도 이식해야 합니다.
  - WKWebView JS 주입(`WKUserScript`) — standalone 모드 스푸프, PushManager 스텁
  - 홈 화면 위젯 6종 (식단·식단 상세·세탁·세탁 상세·워시타워·출석) —
    **WidgetKit(Swift)으로 재구현 필요** (Kotlin 로직을 1:1 이식).
    워시타워 소스 직접 연결(QR 딥링크)도 함께 이식 대상. 이게 주요 작업량입니다.
- 보너스: iOS WKWebView는 16.4+에서 Web Push를 지원하므로, Android에서 막혔던 앱 내 푸시가 기존 서버 Web Push(VAPID) 파이프라인으로 동작할 가능성이 있습니다.

### 인증서/배포 — 핵심 제약

| 방식 | 비용 | 유효 기간 | 대상 | 비고 |
|---|---|---|---|---|
| **Apple Developer Program + TestFlight** | **$99/년** | 빌드당 **90일** | 외부 테스터 100명 | 자동 업데이트, 기관/단체 배포의 사실상 유일한 실용 경로 |
| **무료 개인 계정 사이드로드** | 0원 | **7일** | Apple ID당 기기 3대 | 매주 재서명 필요 (아래 참고) |
| Enterprise ($299/년) | $299 | 1년 | 조직 내부 | 교육기관 자격 심사가 까다로워 현실적으로 어려움 |

**무료(7일) 사이드로드를 고른다면:**

- Xcode로 직접 설치하면 **7일마다 수동 재서명**이 필요합니다.
- **AltStore/AltServer**를 쓰면 맥이 켜져 있고 아이폰이 같은 네트워크에 도달 가능할 때 **자동 재서명**됩니다(셀프 힐링). 조건이 안 맞는 날은 앱·위젯이 비활성화되었다가 다음 재시도 때 복구됩니다.
- 앱 데이터는 재서명 시 보존됩니다.

**정리:** 개인 1~3대 용도면 무료 사이드로드로 충분하고, 여러 명에게 배포(예: 교육기관 내부 전달)하려면 TestFlight($99/년)가 유일하게 현실적입니다. PWA(홈 화면 추가)는 0원이지만 홈 화면 위젯은 제공되지 않습니다.

### 빌드 절차 (원격 맥 기준)

```bash
git clone <이 포크> && cd jungle-bell-Mobile/frontend
npm ci && npm run build
npx cap sync ios        # ios/ 플랫폼이 커밋되어 있어야 함 (현재 미추가)
open ios/App.xcworkspace  # Xcode에서 서명 팀 선택 후 Cmd+R
```

시그니처 이슈 요약: 무료 팀은 7일 만료 + 기기 3대 제한, 유료 팀은 90일(TestFlight) + 100대. 자세한 트레이드오프는 위 표 참고.
